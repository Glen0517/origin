# CAN节点通信消息ID和数据格式设计

## 1. 消息ID结构

### 现有ID格式（保留兼容）
```
0x9555AAA0 - BBB节点
0x9555AAA1 - 资源管理器
0x9555AAA2 - 双向转换器
0x9555AAA3 - PV转换器
0x9555AAA4 - 电池转换器
0x9555AAA5 - 风力涡轮机转换器
```

### 扩展ID结构设计（基于29位扩展帧）
```
Bit: 28 27 26 25 24 23 22 21 20 19 18 17 16 15 14 13 12 11 10 09 08 07 06 05 04 03 02 01 00
     |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |
     9  5  5  5  |     节点类型     |      节点ID      | 消息类型 |  功能码  |  优先级  |
```

- **固定前缀** (28-25): 0x9555（兼容现有系统）
- **节点类型** (24-20): 5位，表示节点的设备类型
- **节点ID** (19-14): 6位，区分同一类型的不同节点
- **消息类型** (13-10): 4位，表示消息的基本类型
- **功能码** (09-05): 5位，特定于消息类型的功能代码
- **优先级** (04-00): 5位，控制消息的优先级

## 2. 消息类型定义

| 类型码 | 消息类型     | 描述                       | 传输频率  | 优先级范围 |
|--------|--------------|----------------------------|-----------|------------|
| 0x0    | 紧急消息     | 系统故障、危险警报         | 事件触发  | 0x00-0x07  |
| 0x1    | 控制命令     | 执行器控制、模式切换       | 按需发送  | 0x08-0x0F  |
| 0x2    | 状态更新     | 系统状态、节点运行信息     | 1-10Hz    | 0x10-0x17  |
| 0x3    | 数据采集     | 传感器数据、测量值         | 10-100Hz  | 0x18-0x1F  |
| 0x4    | 配置参数     | 系统配置、校准数据         | 按需发送  | 0x20-0x27  |
| 0x5    | 心跳消息     | 节点在线状态               | 1Hz       | 0x28-0x2F  |
| 0x6    | 诊断信息     | 自诊断结果、错误日志       | 低频率    | 0x30-0x37  |
| 0x7    | 网络管理     | 节点发现、网络维护         | 低频率    | 0x38-0x3F  |

## 3. 标准数据格式（CAN_DATA扩展）

### 基本数据结构扩展
```c
// 扩展的CAN_DATA结构体
typedef struct {
    Uint32 id;          // 消息ID
    int16 data0;        // 主要数据字段0
    int16 data1;        // 主要数据字段1
    int16 data2;        // 主要数据字段2
    int16 data3;        // 扩展数据字段3 (新)
    int16 index;        // 消息索引/类型标识
    Uint8 status;       // 状态标志 (新)
    Uint8 checksum;     // 校验和 (新)
} EXTENDED_CAN_DATA;
```

### 特殊数据格式定义

#### 3.1 传感器数据格式
```
数据0: 传感器原始值（高12位）+ 传感器ID（低4位）
数据1: 传感器处理后值
数据2: 采样时间戳（低16位）
索引: 传感器类型标识
```

#### 3.2 控制命令格式
```
数据0: 命令代码
数据1: 命令参数1
数据2: 命令参数2
索引: 目标设备标识
```

#### 3.3 状态信息格式
```
数据0: 运行状态标志
数据1: 错误码
数据2: 运行时间/计数
索引: 状态类型标识
```

#### 3.4 心跳消息格式
```
数据0: 节点健康状态码
数据1: 工作模式
数据2: 系统负载百分比
索引: HEART_BEAT_INDEX (0)
```

## 5. 消息优先级配置

### 优先级设计原则
- 安全相关消息（警报、紧急停车）: 最高优先级 (0-7)
- 控制命令消息: 高优先级 (8-15)
- 常规状态更新: 中等优先级 (16-23)
- 传感器数据: 中低优先级 (24-31)
- 心跳消息: 低优先级 (32-39)
- 诊断和配置消息: 最低优先级 (40-47)

## 6. 数据传输约定

### 6.1 周期性数据传输
- **高频率数据** (100Hz): 关键传感器数据，使用循环发送
- **中频率数据** (10Hz): 常规状态信息，使用轮询发送
- **低频率数据** (1Hz): 心跳和配置信息，定时发送

### 6.2 事件触发传输
- 阈值触发: 传感器数据超过预设阈值时立即发送
- 状态变化触发: 设备状态改变时立即发送
- 错误触发: 检测到错误或异常时立即发送

### 6.3 数据一致性保障
- 使用时间戳确保数据同步
- 消息序号防止数据丢失检测
- CRC校验保证数据完整性

## 7. 特殊功能消息定义

### 7.1 网络发现消息
用于新节点加入网络时的自动识别和配置

### 7.2 远程帧请求
用于按需获取特定节点的数据

### 7.3 同步消息
用于多节点协同工作时的时间同步

### 7.4 配置广播消息
用于网络参数的统一配置
