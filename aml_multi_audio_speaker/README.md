# AML 多音频音箱系统架构文档
## 1. 系统架构概览

### 1.1 架构层次

```
┌───────────────────────────────────────────────────────────────┐
│                     应用层                                   │
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │
│ │ 主程序  │ │ 业务逻辑│ │ 事件处理│ │ 配置管理│ │ 生产测试│ │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │
├───────────────────────────────────────────────────────────────┤
│                     核心模块层                               │
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │
│ │ 音频核心│ │ 音频源  │ │ 播放控制│ │ 音量控制│ │ 外设管理│ │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │
├───────────────────────────────────────────────────────────────┤
│                     基础服务层                               │
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │
│ │ 内存管理│ │ 错误处理│ │ 安全管理│ │ 功耗管理│ │ 配置管理│ │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │
├───────────────────────────────────────────────────────────────┤
│                     系统服务层                               │
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │
│ │ 资源管理│ │ 进程管理│ │ 线程池  │ │ 事件系统│ │ IPC通信 │ │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │
└───────────────────────────────────────────────────────────────┘
```

### 1.2 模块依赖关系

核心模块依赖基础服务层提供的服务，基础服务层依赖系统服务层提供的底层功能。所有模块通过依赖注入容器进行管理，实现松耦合的设计。

## 2. 核心功能模块

### 2.1 音频核心 (audio_core)
- **功能**：音频解码、混音、音效处理
- **依赖**：内存管理、配置管理
- **接口**：`audio_core_init()`, `audio_core_play_tone()`, `audio_core_stop_test_audio()`

### 2.2 音频源管理 (audio_source)
- **功能**：音源切换、音频流管理
- **依赖**：配置管理
- **接口**：`audio_source_init()`, `audio_source_switch_next()`, `audio_source_event_poll()`

### 2.3 播放控制 (play_ctrl)
- **功能**：播放状态管理、音效模式切换
- **依赖**：音频核心
- **接口**：`play_ctrl_init()`, `play_ctrl_set_state()`, `play_ctrl_event_poll()`

### 2.4 音量控制 (volume_ctrl)
- **功能**：主音量、低音、高音调节
- **依赖**：配置管理
- **接口**：`volume_ctrl_init()`, `volume_ctrl_master_up()`, `volume_ctrl_bass_up()`

### 2.5 外设管理 (peripheral)
- **功能**：按键处理、红外学习
- **依赖**：配置管理
- **接口**：`peripheral_init()`, `peripheral_start_ir_learn()`, `peripheral_event_poll()`

## 3. 可选功能模块

### 3.1 蓝牙 (bluetooth)
- **功能**：蓝牙连接、音频流传输
- **依赖**：配置管理
- **接口**：`bluetooth_init()`, `bluetooth_event_poll()`

### 3.2 HDMI ARC (hdmi_arc)
- **功能**：HDMI音频回传通道管理
- **依赖**：配置管理
- **接口**：`hdmi_arc_init()`, `hdmi_arc_event_poll()`

### 3.3 SPDIF (spdif_optical)
- **功能**：数字音频接口管理
- **依赖**：配置管理
- **接口**：`spdif_optical_init()`, `spdif_optical_event_poll()`

### 3.4 WiFi媒体 (wifi_media)
- **功能**：WiFi网络连接、DLNA/AirPlay支持
- **依赖**：配置管理
- **接口**：`wifi_media_init()`, `wifi_media_event_poll()`

### 3.5 低音炮通信 (subwoofer_comm)
- **功能**：低音炮设备管理、音频同步
- **依赖**：配置管理
- **接口**：`subwoofer_comm_init()`, `subwoofer_comm_event_poll()`

## 4. 基础服务模块

### 4.1 内存管理 (memory_manager)
- **功能**：内存分配、内存池管理、内存泄漏检测
- **接口**：`memory_manager_init()`, `memory_manager_check_leaks()`

### 4.2 错误处理 (error_handler)
- **功能**：错误记录、错误统计、错误恢复
- **接口**：`error_handler_init()`, `error_handler_report()`

### 4.3 安全管理 (security_manager)
- **功能**：固件完整性检查、网络安全、输入验证
- **接口**：`security_manager_init()`, `security_manager_check_firmware()`

### 4.4 功耗管理 (power_manager)
- **功能**：功耗模式管理、空闲检测、动态轮询频率调整
- **接口**：`power_manager_init()`, `power_manager_check_idle()`

### 4.5 配置管理 (config_manager)
- **功能**：配置文件读取、配置项管理、配置热加载
- **接口**：`config_manager_init()`, `config_manager_get_int()`

## 5. 系统服务模块

### 5.1 资源管理 (res_manager)
- **功能**：资源加载、资源释放、资源监控
- **接口**：`res_manager_init()`, `res_load_resource()`

### 5.2 进程管理 (process_manager)
- **功能**：进程监控、进程间通信、进程状态管理
- **接口**：`process_manager_init()`, `process_manager_monitor()`

### 5.3 线程池 (thread_pool)
- **功能**：线程管理、任务调度、并行处理
- **接口**：`thread_pool_init()`, `thread_pool_submit_task()`

### 5.4 事件系统 (event_system)
- **功能**：事件分发、事件处理、事件队列管理
- **接口**：`event_system_init()`, `event_system_submit()`

### 5.5 IPC通信 (ipc)
- **功能**：进程间通信、消息传递、同步机制
- **接口**：`ipc_init()`, `ipc_send_message()`

## 6. 依赖注入机制

### 6.1 依赖注入容器

系统使用 `DependencyContainer_t` 结构体作为依赖注入容器，管理所有模块的实例。容器中的模块分为两类：

1. **服务模块**：使用具体类型的指针（如 `MemoryManager_t *memory_manager`）
2. **功能模块**：使用 `ModuleState_e` 枚举表示状态（如 `ModuleState_e audio_core`）

### 6.2 模块初始化流程

1. 初始化基础服务模块（内存管理、错误处理、安全管理等）
2. 初始化核心功能模块（音频核心、音频源、播放控制等）
3. 初始化可选功能模块（蓝牙、HDMI ARC、SPDIF等）
4. 初始化生产测试模块

### 6.3 模块依赖关系

- 核心模块依赖基础服务模块
- 可选模块依赖核心模块和基础服务模块
- 所有模块通过依赖注入容器获取依赖

## 7. 事件处理机制

### 7.1 轮询配置

系统使用统一的轮询配置数组 `ModulePollConfig` 管理所有模块的事件轮询：

```c
ModulePollConfig poll_configs[] = {
    {bluetooth_event_poll, 50, 0},        // 蓝牙事件：每50毫秒轮询一次
    {audio_source_event_poll, 50, 0},     // 音频源事件：每50毫秒轮询一次
    {play_ctrl_event_poll, 10, 0},        // 播放控制事件：每10毫秒轮询一次
    {system_event_poll, 2000, 0},         // 系统事件：每2秒轮询一次
#ifdef CONFIG_ENABLE_BT_MESH
    {subwoofer_comm_event_poll, 100, 0},  // 低音炮通信事件：每100毫秒轮询一次
#endif
    // 其他可选模块...
    {NULL, 100, 0}                        // 结束标记
};
```

### 7.2 事件轮询机制

- **Linux平台**：使用 `epoll` 和 `timerfd` 实现事件驱动
- **非Linux平台**：使用传统轮询方式
- **动态轮询频率**：根据系统负载和功耗模式自动调整轮询间隔

## 8. 配置管理

### 8.1 配置文件结构

配置文件存储在以下路径：
- 量产环境：`/etc/aml_soundbar/config/`
- 开发环境：`./config/`

### 8.2 配置项类型

- 整数类型：音量、采样率、缓冲大小等
- 布尔类型：功能开关、使能状态等
- 字符串类型：设备名称、蓝牙PIN码等

### 8.3 配置热加载

系统支持配置文件的热加载，无需重启即可应用新的配置。

## 9. 功耗管理

### 9.1 功耗模式

- **正常模式**：全功能运行，轮询频率高
- **低功耗模式**：关闭非必要功能，降低轮询频率
- **待机模式**：仅保留必要的唤醒功能

### 9.2 动态功耗调整

- **空闲检测**：根据系统活动状态自动调整功耗模式
- **轮询频率调整**：根据功耗模式调整模块轮询间隔
- **功能降级**：在低功耗模式下关闭非必要功能

## 10. 安全管理

### 10.1 固件安全

- **固件完整性检查**：启动时检查固件完整性
- **固件版本管理**：检测并提示固件更新

### 10.2 网络安全

- **输入验证**：对所有网络输入进行验证
- **网络访问控制**：限制网络访问权限

### 10.3 系统安全

- **权限管理**：限制敏感操作的权限
- **错误处理**：安全的错误处理机制，避免信息泄露

## 11. 生产测试

### 11.1 硬件自检

- **模块状态检查**：检查各模块的初始化状态
- **功能测试**：测试核心功能的可用性

### 11.2 老化测试

- **长时间运行测试**：模拟设备长时间运行的情况
- **音频测试**：播放测试音频，验证音频系统的稳定性

### 11.3 EQ校准

- **频率响应校准**：校准音频系统的频率响应
- **音量平衡校准**：校准左右声道的音量平衡

## 12. 系统启动流程

1. 初始化基础服务（内存管理、错误处理等）
2. 初始化系统服务（资源管理、进程管理等）
3. 播放开机提示音
4. 初始化核心模块（音频核心、音频源等）
5. 初始化可选模块（蓝牙、HDMI等）
6. 进入业务主循环

## 13. 系统退出流程

1. 接收到退出信号（SIGINT、SIGTERM）
2. 停止业务主循环
3. 反初始化所有模块
4. 释放系统资源
5. 退出系统

## 14. 代码优化建议

### 14.1 性能优化

- 使用内存池减少内存分配开销
- 使用epoll替代poll提高事件处理效率
- 动态调整轮询频率，平衡性能和功耗

### 14.2 可靠性优化

- 完善错误处理机制，提高系统容错能力
- 实现内存泄漏检测，避免内存泄漏
- 增加系统监控，及时发现并处理异常

### 14.3 可维护性优化

- 使用依赖注入减少模块间耦合
- 统一事件处理机制，提高代码复用性
- 完善配置管理，支持配置热加载

## 15. 扩展建议

### 15.1 功能扩展

- 添加语音助手支持
- 实现多房间音频同步
- 支持更多音频格式和编码

### 15.2 平台扩展

- 支持更多嵌入式Linux平台
- 适配不同硬件配置的设备
- 提供跨平台的抽象层

### 15.3 集成扩展

- 集成智能家居平台（如HomeKit、Google Home）
- 支持更多音频服务（如Spotify、Tidal）
- 提供开放的API接口，支持第三方集成

## 16. 总结

AML多音频音箱系统采用分层架构设计，通过依赖注入实现模块解耦，使用统一的事件处理机制提高代码复用性。系统支持多种音频源、音效处理和智能功耗管理，可根据不同产品类型和硬件配置进行灵活配置。

通过持续的性能优化、可靠性提升和功能扩展，系统能够满足不同用户的需求，为用户提供高质量的音频体验。
