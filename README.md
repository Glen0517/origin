# 四轴飞行控制器项目

## 项目简介

这是一个四轴飞行控制器的硬件抽象层(HAL)和平台抽象层(PAL)实现，提供了跨平台的硬件访问接口。项目设计遵循模块化、可移植性和可测试性原则，支持在不同硬件平台上快速移植和部署。

## 硬件抽象层(HAL)

硬件抽象层提供了统一的硬件访问接口，屏蔽了不同硬件平台的差异性。主要包含以下模块：

### GPIO模块
- 支持多种GPIO配置（输入、输出、复用功能）
- 支持输出类型配置（推挽、开漏）
- 支持上下拉电阻配置
- 支持中断触发配置

### UART模块
- 支持多种波特率配置
- 支持不同的数据位、停止位和校验位配置
- 支持硬件流控
- 提供字节和缓冲区收发功能

### SPI模块
- 支持主/从模式配置
- 支持多种时钟极性和相位组合
- 支持不同的数据大小
- 支持半双工和全双工通信
- 支持软件和硬件NSS控制

### I2C模块
- 支持主/从模式配置
- 支持标准模式和快速模式
- 支持7位和10位地址模式
- 提供设备检测、读写功能

## 平台抽象层(PAL)

平台抽象层提供了与底层硬件平台无关的系统服务接口，主要功能包括：

- 系统初始化
- 延时函数（毫秒、微秒）
- 时钟管理
- 系统复位
- CPU ID获取
- 内存信息获取
- 平台信息查询

平台抽象层支持多种平台实现，可以通过注册机制切换不同的实现。

## 编译指南

### Windows环境

1. 确保已安装GCC编译器（推荐使用MinGW或TDM-GCC）
2. 打开命令提示符，导航到项目目录
3. 执行编译脚本：

```batch
compile_win.bat
```

编译脚本会自动：
- 清理之前的编译结果
- 编译主程序和测试程序
- 显示编译信息和程序大小

### 编译选项

编译脚本中使用的主要编译选项：
- `-Wall` - 启用所有警告
- `-Wextra` - 启用额外警告
- `-Werror` - 将警告视为错误
- `-g` - 生成调试信息
- `-O0` - 不进行优化，便于调试
- `-std=c11` - 使用C11标准

## 测试框架

项目包含一个功能完善的测试框架，用于验证各个模块的功能：

### 运行测试

编译完成后，可以直接运行生成的测试程序：

```batch
test_hal.exe
```

### 测试功能

测试框架支持：
- 详细的测试结果报告
- 测试统计信息（通过/失败/跳过的测试数量和百分比）
- 模拟环境支持（无需实际硬件即可进行测试）
- 错误处理和恢复机制

### 模拟环境

在没有实际硬件的环境中，可以通过修改`hal_test.c`中的`IS_SIMULATION_ENV`宏来启用模拟模式：

```c
#define IS_SIMULATION_ENV (1)  // 1=模拟环境，0=实际硬件
```

在模拟环境中，测试框架会模拟硬件行为，使测试可以在任何平台上运行。

## 开发规范

### 代码风格
- 使用缩进4个空格
- 花括号使用K&R风格（左花括号不换行）
- 变量和函数命名使用小写字母加下划线
- 类型定义使用小写字母加下划线，以`_t`结尾
- 宏定义使用大写字母加下划线

### 注释规范
- 使用Doxygen风格的注释
- 每个模块、结构体、枚举和函数都应有详细注释
- 注释应包含简要描述、参数说明、返回值说明和注意事项

### 错误处理
- 函数返回布尔值表示成功或失败
- 复杂操作应检查参数有效性
- 关键操作应有超时处理
- 错误信息应清晰明了

## 移植指南

### 支持新的硬件平台

1. 在`platform`目录下创建新的平台实现文件（如`platform_new_platform.c`）
2. 实现`platform.h`中定义的所有接口函数
3. 创建注册函数`platform_register_new_platform_impl()`
4. 在应用程序中调用注册函数切换到新平台

### 扩展硬件抽象层

1. 在`hal`目录下创建新的硬件模块文件（如`hal_new_module.h`和`hal_new_module.c`）
2. 定义统一的接口和数据结构
3. 实现模块功能，调用平台抽象层接口进行底层访问
